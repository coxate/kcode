# Kcode MCP 客户端 Spec

> 状态：已批准
> 适用版本：Kcode v0.4.0 后续功能版本

## 背景

Kcode 当前具有多轮 Agent Loop、Anthropic/OpenAI Provider、六个内置工具、并发调度、权限模式、危险命令拦截和文件沙箱，但工具集合固定在源码中。

MCP 使用统一协议连接外部工具服务。引入 MCP 客户端后，Kcode 可以通过配置接入 GitHub、数据库和内部服务，而不必为每种能力修改 Provider 或 Agent 编排代码。

MCP server 本身是新的安全边界：stdio server 是 Kcode 启动的本地程序，可能执行任意代码；HTTP server 可以连接外部地址，并可能通过请求头发送凭据。因此，MCP server 的启动信任必须发生在工具调用权限之前。

## 目标

- 通过配置发现和连接多个 MCP server。
- 支持 stdio 与 Streamable HTTP。
- 将远端工具适配为 Kcode 的统一工具抽象。
- 保持 Anthropic 和 OpenAI Provider 无需感知工具来源。
- 将 MCP 工具纳入现有权限模式、规则和并发调度。
- 对项目级 MCP 配置实施首次信任确认。
- 隔离单个 server 的连接、调用和关闭故障。
- 防止 MCP 凭据出现在配置、日志、界面或模型上下文中。
- 不破坏 Kcode v0.4.0 的既有行为。

## 功能需求

### F1：两层配置加载与合并

从用户级 `~/.kcode/config.yaml` 与项目级 `<project>/.kcode/config.yaml` 读取 `mcp_servers`。该字段为以 server 名为键的映射；项目级同名 server 完整覆盖用户级定义，不做字段级合并。配置文件缺失时视为该层没有 MCP server。

配置错误按故障域处理：整份 YAML 无法解析或核心 Provider 配置无效时，保持 Kcode 当前行为并阻止启动；`mcp_servers` 段类型错误时忽略该段并告警；单个 server 定义错误时只跳过该 server 并告警。

### F2：Server 类型与字段

每个 server 必须显式声明 `type`：

- `stdio`：必填非空字符串 `command`；可选字符串数组 `args`；可选字符串映射 `env`。
- `http`：必填绝对 `http` 或 `https` URL `url`，且 URL 不允许包含用户名或密码；可选字符串映射 `headers`。

缺少必填字段、字段类型错误或类型不受支持时，跳过该 server。

### F3：项目级 Server 首次信任

所有项目级 MCP server 在首次连接或启动前必须显示信任确认。确认信息包括项目路径、server 名和类型、stdio 的 command 与 args、HTTP 的目标协议/主机/端口/路径，以及将引用的环境变量名称；不得显示环境变量值或凭据。

允许后，Kcode 按“规范化项目身份 + server 名 + 完整未展开配置”生成不可逆配置指纹并记录信任。command、args、url、env、headers、server 类型或名称、项目位置或身份发生变化时必须重新确认。用户级配置视为用户主动配置，不重复询问。用户必须能够清除已保存的 MCP 信任记录。

拒绝或取消确认时只跳过对应 server，不阻止 Kcode 启动。

### F4：环境变量展开与秘密管理

仅 `env` 和 `headers` 的值支持 `${VAR}` 插值；既支持完整值，也支持 `Bearer ${TOKEN}`，一个值可以引用多个变量。server 名、类型、command、args 和 URL 不做变量展开。

展开顺序为：完成项目级信任确认、检查所有变量是否存在、展开变量、建立连接或启动进程。引用的变量不存在时跳过该 server 并告警，告警只显示变量名。

所有展开出的非空值必须加入 Kcode 的敏感值集合，用于界面、审批预览、日志、错误和工具结果脱敏。

### F5：stdio 环境隔离

stdio 子进程只自动继承程序查找路径、系统临时目录、用户目录和语言区域等跨平台基础环境。其他变量只有在 server 的 `env` 中被明确引用或设置后才会传给子进程；配置 `env` 覆盖同名基础变量。

子进程通过标准输入输出与 MCP SDK 通信。server 的 stderr 可以转发到诊断输出，但必须经过敏感值脱敏。

### F6：Streamable HTTP

HTTP server 通过 Streamable HTTP endpoint 连接，配置 headers 注入请求。客户端允许 SDK 处理 JSON 或 SSE 形式的请求响应，但不消费工具列表变化、调用进度，以及 resources、prompts、sampling、roots 等服务器主动能力。

### F7：标准会话与 SDK 约束

每个 server 依次完成建立传输、MCP 初始化握手、获取工具列表和按需调用工具。协议编解码、请求 ID、能力协商和传输由官方 MCP Python SDK 承担，不自研协议栈。项目必须锁定经过测试的 SDK 主版本范围。

### F8：动态工具适配

每个远端工具适配为 Kcode 工具：

- 名称为 `mcp__<server>__<tool>`；
- 描述使用远端描述，缺失时生成包含 server 和原工具名的说明；
- 完整保留远端 `inputSchema`；
- `readOnlyHint` 严格等于 `true` 时归为只读，其余情况归为有副作用；
- 通过所属 server 的活动会话调用原工具名。

Kcode 的统一工具抽象必须支持运行时 JSON Schema。Provider 和 Agent Loop 只消费统一工具定义，不判断工具来源。

### F9：命名空间与重复处理

完整工具名只允许 `[A-Za-z0-9_-]`。非法名称被跳过并告警。不同 server 的同名工具通过命名空间隔离。同一 server 返回重复工具名时保留第一次出现的定义，跳过后续定义并告警。MCP 工具不得覆盖内置工具。

### F10：结果和错误映射

调用成功时按顺序拼接所有文本内容块，映射为 Kcode 成功结果的 `content` 字段，并保留空文本成功结果。远端声明调用错误时映射为结构化 `mcp_tool_error`。连接断开、协议错误和其他异常必须转成结构化错误，不向 Agent Loop 泄漏未处理异常。

非文本内容块暂不回灌；相同 server、工具和内容类型只告警一次。错误和结果进入日志、界面或模型上下文前必须脱敏。

### F11：权限链路

MCP 工具复用 Kcode 现有权限决策顺序，但对外部工具做最小泛化：危险命令黑名单和文件沙箱仍只检查对应内置工具；MCP 工具不伪装成命令或文件路径；allow/deny 规则支持 MCP 完整工具名和 `*` 通配，例如 `mcp__github__create_issue` 和 `mcp__github__*`。

无匹配规则时，只读 MCP 工具在 default 和 acceptEdits 模式放行；有副作用工具在这两个模式询问；bypassPermissions 模式放行；Plan Mode 只向模型暴露只读 MCP 工具。“始终允许”只记录当前完整工具名。审批界面显示工具名和已脱敏参数预览。

### F12：并发与稳定工具快照

不同 server 的连接、初始化和工具发现并发执行。每个 server 的完整启动序列独立受 30 秒超时限制，用户等待信任确认的时间不计入超时。

主聊天界面进入 Ready 前完成所有已允许 server 的连接尝试；Ready 后本次运行的工具集合保持稳定。多个只读工具遵守 Kcode 现有并发上限，有副作用工具保守串行执行。

### F13：调用超时、取消与失败隔离

每次 MCP 工具调用受 30 秒超时限制。超时映射为 `timeout`，用户取消映射为 `cancelled`。单个 server 的连接、握手、工具发现或调用失败不得影响内置工具、其他 MCP server或当前对话后续轮次。

本版本不自动重连；连接失效后的调用继续返回结构化错误。

### F14：生命周期与关闭

MCP 会话、Textual 应用和工具调用必须运行在兼容的异步生命周期内。每个 server 的传输和会话由长期存活的连接所有者持有，直至 Kcode 退出。

退出时统一关闭连接：stdio 关闭通信并终止子进程；HTTP 关闭会话和客户端；相关异步任务被取消和回收。整体关闭最多等待 5 秒，单个 server 卡住不得阻止程序退出。

### F15：启动反馈

启动后展示成功连接的 server 数量、注册工具数量，以及被拒绝、跳过或失败的 server。输出不得包含请求头、环境变量值或其他凭据。诊断写入 stderr 或现有启动告警区域，不向普通用户展示内部堆栈。

## 非功能需求

- N1：未知副作用、缺失注解和非法注解均按有副作用处理。
- N2：未经信任的项目级 server 不得启动进程、建立网络连接或展开秘密。
- N3：stdio 不继承完整宿主环境；HTTP 只获得显式 headers。
- N4：单个 MCP server 失败不影响核心 Kcode 和其他 server。
- N5：Anthropic 与 OpenAI 使用相同 MCP 工具定义和结果。
- N6：配置示例、信任记录和诊断不保存展开后的秘密。
- N7：不泄漏子进程、HTTP 客户端或异步任务。
- N8：现有会话、流式输出、缓存、规划、权限和取消行为不退化。
- N9：错误指出 server、阶段和安全处理后的原因。
- N10：格式、静态检查和全部自动化测试通过。

## 不做的事

- MCP resources、prompts、sampling 和 roots。
- 工具列表变化和调用进度通知。
- 自动重连、健康检查、退避和配置热加载。
- OAuth 登录和非文本内容回灌。
- server 端实现、速率限制、配额和完整审计平台。
- MCP 参数级权限规则。
- 运行期间增删 server。
- 自动信任任何项目级 MCP 配置。

## 验收标准

- AC1：两层配置按 server 名合并，项目同名定义完整覆盖用户定义；MCP 局部错误不会掩盖核心配置错误。（F1）
- AC2：stdio/http 字段得到校验；非法 server 被独立跳过；HTTP URL 中的用户信息被拒绝。（F2）
- AC3：项目级 server 首次连接前显示确认；相同指纹不重复询问；配置变化重新询问；拒绝后无进程和网络活动。（F3）
- AC4：`${VAR}` 支持完整值和字符串内插；缺失变量跳过单个 server；输出不出现展开值。（F4）
- AC5：stdio 只能看到基础环境和显式 env；未声明 Token 不可见；退出后无残留子进程。（F5）
- AC6：HTTP 收到配置 headers，并能处理 JSON 与 SSE 请求响应；不消费主动能力。（F6）
- AC7：使用锁定版本的官方 SDK 完成初始化、列工具和调用，不存在自研 JSON-RPC。（F7）
- AC8：动态 Schema 完整传递给 Provider；只读注解正确分类；缺失或非法注解按有副作用处理。（F8）
- AC9：跨 server 同名工具互不覆盖；非法名称和重复名称按规定跳过并告警。（F9）
- AC10：文本块按序拼接；远端错误、超时和传输异常映射为结构化结果；非文本告警去重。（F10）
- AC11：精确和通配 MCP 权限规则有效；各权限模式、Plan Mode 和“始终允许”符合 F11。（F11）
- AC12：多个 server 并发启动；单 server 30 秒超时；Ready 后工具快照不变；只读调用遵守并发上限。（F12）
- AC13：调用超时和取消不终止 Agent Loop；一个 server 失效不影响其他工具。（F13）
- AC14：正常退出、启动失败和中断都能关闭会话；关闭不超过 5 秒且无悬挂任务。（F14）
- AC15：启动汇总准确显示成功、跳过和失败数量，且不包含敏感数据。（F15）
- AC16：同一 MCP server 在 Anthropic 和 OpenAI 下产生一致工具定义、权限判断和结果结构。（N5）
- AC17：配置示例只通过环境变量引用秘密；信任记录只保存不可逆指纹；配置中无测试 Token 明文。（N6）
- AC18：Kcode 既有测试全部通过，并新增配置、信任、stdio、HTTP、权限、并发、超时、取消和关闭测试。（N8/N10）

## 学习归属

- 用户已参与并确认：项目级 server 首次确认、配置指纹信任、分层容错、最小环境继承、缺失变量跳过，以及 HTTP 与 stdio 统一信任。
- Codex 协助完成、用户仍需学习：异步生命周期、动态 JSON Schema 适配、秘密传播边界和权限抽象泛化。
