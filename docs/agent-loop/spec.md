# KCode Agent Loop Spec

## 背景

KCode 0.2.0 已具备六个工具、流式响应、结构化工具结果、取消和安全确认，但一次用户请求最多执行一个工具，模型无法根据中间结果自主继续。

## 目标

- 让 KCode 按 ReAct 模式持续“调用模型—执行工具—回灌结果—调整行动”，直到给出最终文本或触发明确停止条件。
- 支持多工具安全调度和只读规划、完整执行两种模式。
- 通过统一异步事件保持 Agent 核心与终端界面解耦。

## 功能需求

- F1: 每个普通请求启动自主循环；模型返回工具时执行并回灌，模型不再请求工具且给出文本时完成。
- F2: 模型流实时转发文本和思考，同时累积完整文本、工具调用、停止原因、连续状态和用量。
- F3: 对外事件覆盖文本、思考、工具生命周期、Token、模式、轮次进度、停止原因和完成状态。
- F4: 支持正常完成、默认 10 轮的可配置上限、用户取消、连续两轮请求未知工具、流或协议错误等停止条件。
- F5: 多工具按模型顺序切批；相邻只读调用最多 4 个并发，副作用调用单独串行，结果按原顺序回灌。
- F6: `/plan` 切入只读规划模式并保留最新完整计划；`/do` 切回执行模式并让下一请求使用一次该计划。
- F7: Plan Mode 中写改和非白名单命令返回结构化拒绝；Do Mode 沿用 0.2.0 的逐工具授权。
- F8: 每个完整工具响应及其整批结果形成历史检查点；异常只丢弃当前不完整响应。
- F9: 每次模型请求产生可选 Token 用量并累计；供应商未返回时明确为未知，不按零计算。

## 非功能需求

- N1: 循环、模型流和工具执行全程异步，不阻塞 Textual 界面。
- N2: 并发有界，事件和回灌顺序确定；副作用工具不得重叠。
- N3: 取消传递到模型流、授权等待、并发任务和命令子进程并清理进程组。
- N4: 兼容 Anthropic、OpenAI 和 DeepSeek，保留各协议要求的思考与连续状态。
- N5: 保持六工具语义、安全策略、旧配置和普通聊天兼容。
- N6: Token、结果、进度与错误继续裁剪和脱敏，API Key 不进入界面历史或日志。
- N7: 自动测试使用假 Provider 和临时工作区，不访问真实 API 或真实用户文件。
- N8: 机器性能和并发完成顺序不得改变历史顺序或停止判定。

## 不做的事

- 不新增或重做权限系统，不实现持久化授权。
- 不实现上下文压缩、会话持久化、跨进程恢复；`/clear` 清除计划并恢复 Do Mode。
- 不新增工具、MCP、子 Agent、多 Agent 或远程执行。
- 不推断多工具依赖图，不为模型流错误自动重试。
- 不实现文件撤销、命令回滚或副作用补偿。
- 不将 Token 换算为金额，也不推算中断流缺失的用量。

## 验收标准

- AC1: 一次请求可自主完成查找、读取、修改和验证并给出最终答复。
- AC2: 六类停止原因准确可见，停止后不再请求模型。
- AC3: 流式文本实时可见，完整响应与供应商流一致。
- AC4: 只读工具有界并发，副作用严格串行，结果稳定排序。
- AC5: `/plan` 只执行读操作并产出计划；`/do` 恢复全部工具并使用最新计划一次。
- AC6: OpenAI、DeepSeek、Anthropic 的 Token 和连续状态正确往返。
- AC7: 异常停止后已完成工具历史仍可用于下一请求。
- AC8: 既有确认框、拒绝回灌、取消和进程清理继续有效。
- AC9: 旧测试与新增循环、并发、模式、用量和 UI 测试全部通过。
- AC10: tmux 中真实 DeepSeek 完成多步只读和经确认写改，输出不泄漏密钥。
