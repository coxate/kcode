# KCode 系统提示工程化 Spec

## 背景

KCode 已具备自主 Agent Loop、六个本地工具、Plan/Do 模式，以及 Anthropic、OpenAI 和 DeepSeek Provider。当前全局指令仍是职责混杂的固定文本；稳定规则、动态环境、模式提醒和历史没有明确分层，难以稳定利用 Provider 的提示缓存。模型也缺少工作目录、平台、日期、git 状态、应用版本和当前模型等运行环境信息。

## 目标

- 把全局指令拆成按职责和优先级装配的模块。
- 把稳定系统模块与工具定义放入可缓存前缀，把环境、补充指令和历史留在动态通道。
- 用独立环境块提供运行上下文，用 `<system-reminder>` 注入不持久化的补充指令。
- 在系统提示和工具描述中双重强化专用工具优先及编辑前先读。
- Plan Mode 在第 1、5、10、15……次模型请求注入完整提醒，其余迭代注入精简提醒。
- 覆盖 Anthropic、OpenAI 和 DeepSeek 的缓存控制与用量字段，并提供离线测试和人工 smoke 验证。

## 功能需求

- F1：每个提示模块包含名称、唯一优先级和内容。七个固定模块依次为身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出；其后预留自定义指令、已激活 Skill、长期记忆三个空槽。空模块自动跳过，非空模块以一个空行分隔。
- F2：每个 Agent 任务构造一次独立环境系统块，包含启动工作目录、操作系统/平台、当前日期、git 状态、应用版本和当前模型。单项采集失败时降级，不中断请求。
- F3：稳定系统模块和确定顺序的工具定义构成缓存前缀；环境、reminder、历史、工具调用和结果属于动态通道。Anthropic 使用显式断点；支持显式断点的官方 OpenAI 模型使用稳定断点与 cache key，旧模型和兼容端点使用自动前缀缓存；DeepSeek 使用自身自动缓存。
- F4：Provider 对外暴露缓存创建和读取 Token。Anthropic 解析 creation/read；OpenAI 解析 `cache_write_tokens`/`cached_tokens`；DeepSeek 解析 `prompt_cache_hit_tokens`，miss 不映射为创建。缺失字段保持未知。
- F5：专用工具优先和编辑前先读同时写入稳定系统提示和相关工具描述；本阶段不增加执行器硬拦截。
- F6：新增内部专用 system-reminder 消息类型，序列化时用 `<system-reminder>` 包裹。它按请求动态生成，不进入持久历史，不冒充用户输入，不破坏工具调用与结果配对。
- F7：Plan Mode reminder 按模型请求迭代计数：第 1 次及每个 5 的倍数使用完整版，其余使用精简版。Plan Mode 继续只开放只读工具；`/do` 恢复全部工具并一次性消费已保存计划。
- F8：三类 Provider 使用相同模块内容、环境字段、reminder 内容与注入节奏；协议层只映射各自消息、缓存控制和用量字段。

## 非功能需求

- N1：配置、工具集合和内置提示版本不变时，缓存前缀逐字节稳定。
- N2：Agent Loop、流式输出、调度、授权、取消、停止条件、历史检查点和连续状态不退化。
- N3：动态注入不进入持久历史，且各 Provider 消息结构合法。
- N4：git 探测快速、有界、无 shell；失败、超时、非仓库均可降级。
- N5：环境、错误、调试输出和 TUI 不泄漏 API Key 或敏感环境变量。
- N6：缓存字段缺失、为空或类型异常时保持未知，不中断流。
- N7：保持 Python 3.11+ 和 macOS/Linux/Windows 兼容；pytest 与 Ruff 检查通过。
- N8：新增模块或 reminder 时只需局部注册，不修改装配算法。
- N9：协议缓存差异只存在于 Provider 层。
- N10：默认测试不访问真实 API、不读取真实用户文件、不产生模型费用。

## 不做的事

- 不加载项目指令文件，不接入 Skill/MCP，不实现长期记忆。
- 不允许三个预留槽接入真实内容来源。
- 不建立自动评测框架，只做人工定性对比。
- 不缓存历史，不配置 TTL、断点数量、模块优先级或 reminder 间隔。
- 不在正常 TUI 展示缓存字段，不新增自动联网 smoke 脚本。
- 不实现提示热加载、外部模板或执行器“编辑前已读”硬约束。
- 不新增 Provider 协议，不因缓存字段不兼容自动重试。

## 验收标准

- AC1：七个固定模块按规定顺序装配；新增测试模块无需修改装配算法。
- AC2：三个可选空槽不产生标题或多余空行。
- AC3：环境块包含六项字段；非 git、git 缺失和超时均可降级。
- AC4：动态环境、历史和迭代变化不改变稳定提示及工具定义字节。
- AC5：Anthropic 稳定块有唯一显式断点；OpenAI 显式模式有 breakpoint、稳定 key 和 explicit policy；自动模式无这些字段。
- AC6：三类 Provider 正确解析缓存字段；缺失和异常字段保持未知。
- AC7：真实 smoke 在满足供应商阈值时观察到首次缓存写入和后续读取；不支持缓存的端点报告未知。
- AC8：两条关键规则同时出现在系统提示和相关工具描述中。
- AC9：reminder 正确包裹、冲突标签转义，且任何停止路径后均不进入历史。
- AC10：第 1、5、10 次为完整 Plan reminder，其余为精简版；Plan/Do 工具边界保持正确。
- AC11：三类 Provider 序列化合法，中途取消后仍可继续请求。
- AC12：现有 Agent、Provider、工具、历史、TUI 和配置测试全部通过。
- AC13：环境采集有界且不泄漏密钥。
- AC14：pytest、`ruff format --check` 和 `ruff check` 通过，测试无真实网络访问。
- AC15：人工对比专用工具、编辑前读取、Plan 只读、环境利用和最终回答质量。
