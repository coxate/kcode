# KCode 工具系统 Spec

## 背景与目标

KCode 0.1.0 已支持多 Provider、流式文本、thinking、多轮会话和取消，但模型不能操作开发环境。本阶段增加统一工具系统：模型每轮最多选择一个工具，KCode 执行并回灌结果，再由模型生成最终文本。

## 功能需求

- F1: 工具统一提供名称、描述、参数 Schema 和异步执行入口，并由注册中心集中登记、查找和导出定义。
- F2: 内置 `read_file`、`write_file`、`edit_file`、`run_command`、`find_files`、`search_code` 六个工具。
- F3: 读文件支持按行分段；写文件只创建；改文件仅在原文唯一匹配时原子替换。
- F4: 命令返回退出码、标准输出、标准错误和耗时，支持超时、取消与进程清理。
- F5: 查找和搜索结果稳定排序，支持 glob、正则、数量限制和不可读目标警告。
- F6: 相对路径以启动目录为基准；全盘可读，工作区外写改需要单次确认。
- F7: 严格只读命令免确认，其他命令必须确认；拒绝后不得执行。
- F8: 所有失败均转换为结构化结果，且经过裁剪和密钥脱敏。
- F9: Anthropic 与 OpenAI 兼容 Provider 均解析流式工具参数碎片并保存协议要求的连续状态。
- F10: 一轮最多两次模型请求和一次工具执行；多个工具调用整批拒绝，第二次再次请求工具时停止。
- F11: 完整工具轮次才提交历史；TUI 展示工具状态，Ctrl+C 可在任意阶段取消。

## 非功能需求

- 文件工具默认 10 秒；命令默认 30 秒且限制为 1–120 秒。
- 单次内容约 256 KiB；查找和搜索最多 500 项；达到限制必须标记截断。
- 保持 macOS、Linux、Windows 与现有纯对话行为兼容。
- 默认测试不访问真实 API、真实用户文件或产生费用。

## 不做的事

不实现 Agent Loop、多工具执行、并发工具、Plan Mode、MCP、持久化授权、二进制编辑或文件撤销。

## 验收标准

- AC1: 六工具可注册、查找并导出两种 Provider 的定义，重复名称失败。
- AC2: 分段读取可无遗漏拼接；写入不覆盖；编辑只有唯一匹配才成功。
- AC3: 命令成功、非零退出、截断、超时和取消均返回正确结构化结果并清理进程。
- AC4: 查找和搜索稳定、可截断，坏路径和权限问题不使应用崩溃。
- AC5: 路径与符号链接按真实目标授权；需要确认的操作在拒绝后不执行。
- AC6: OpenAI 与 Anthropic 的跨片段工具参数可正确还原，Anthropic thinking 签名原样往返。
- AC7: 单工具流程严格执行两次请求；多调用、未知工具、坏参数和第二次工具请求行为可观测。
- AC8: 成功历史完整，取消历史为空；TUI 状态与四阶段取消正确。
- AC9: 编译与完整测试通过，真实端到端输出不包含 API Key。
