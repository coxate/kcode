# KCode 上下文管理 Checklist

> 2026-08-07 离线验收：默认测试使用 Fake Provider，不联网、不调用真实模型。未勾选的任务质量条目需要后续真实模型或人工评测，不能仅由单元测试证明。

## 文档与范围

- [x] `spec.md`、`plan.md`、`task.md` 和 `checklist.md` 均存在且版本一致。
- [x] 原始附件未被覆盖，KCode 工作树中的无关改动未被修改。
- [x] 本章没有新增独立摘要 Provider 配置。
- [x] 本章没有改变工具、权限、MCP、计划模式和 Agent Loop 的既有业务语义。

## 第一层 Artifact 外置

- [x] 单个工具结果超过 50000 UTF-8 字节时只在模型视图中保留预览和 Artifact 引用。
- [x] 预览包含字节数、工具名、工具调用 ID、路径、头部内容和重读提示。
- [x] 同批结果超过 200000 字节时按字节从大到小选择，字节相同时按原始调用顺序选择。
- [x] 工具调用与工具结果的配对和原始顺序保持不变。
- [x] 第一层不调用 LLM，Fake Provider 的调用次数不增加。
- [x] Artifact 只保存脱敏内容，不包含 Provider Key 或 MCP 凭据。
- [x] 同一工具调用 ID 重复处理时不重复写文件，替换文本逐字节一致。
- [x] 原子写入失败时不写完成决策，下一次允许重新尝试。
- [x] Artifact 范围读取不会无条件再次返回同一个 Artifact 指针。

## 第二层 Context Compaction

- [x] Context Manager 区分规范记录和模型视图。
- [x] 摘要不覆盖或删除规范记录。
- [x] 摘要请求不传工具定义，并固定禁止工具调用。
- [x] 摘要不依赖 `<analysis>` 草稿协议。
- [x] 摘要能解析目标、确认事实、推测、未知项、决策、文件、错误、当前状态、待办、下一步和 Artifact 引用。
- [ ] 摘要不能把未提供内容写成已确认事实。
- [x] 摘要失败时旧模型视图和规范记录保持不变。
- [x] 摘要请求丢弃历史组时设置 `history_incomplete=true`。
- [x] 摘要覆盖范围、来源指纹和近期原文状态可被下一轮继续使用。

## 近期原文与恢复

- [x] 近期原文至少达到 10000 Token 且至少保留 5 条消息，除非已经到达历史开头。
- [x] 保留边界不会拆开工具调用和对应工具结果。
- [x] 恢复最多 5 个最近成功读取的文件。
- [x] 文件快照包含路径、读取时间和截断标记。
- [x] 文件快照明确表示它是历史副本，不保证是当前文件内容。
- [x] 恢复段中的工具集合与同轮 Provider 请求的工具集合完全一致。
- [x] 边界提示要求模型需要精确内容时重新读取，禁止依据摘要脑补。

## Token 与 Provider

- [x] Provider usage 被归一化为上下文输入、输出、缓存读写、精确性和置信度。
- [x] 缓存 Token 不会与已包含缓存的输入 Token 重复相加。
- [x] 上一次精确 usage 作为锚点被替换保存，而不是累计相加。
- [x] 锚点之后的新消息使用字符数除以 3.5 的近似估算。
- [x] 缺失或非法 usage 不会按零处理。
- [x] 预算计算分离上下文窗口、摘要输出预留和自动/手动安全余量。
- [x] `context_window` 按显式配置、模型元数据、Provider 保守默认值顺序解析。
- [x] Prompt Cache 只验证前缀稳定条件，不断言 Provider 必然命中。

## Agent、UI 与异常

- [x] Runner 每轮只计算一次工具集合，并将同一引用用于恢复段和 Provider 请求。
- [x] 工具完成后按文件追踪、Artifact 状态、规范记录的顺序更新。
- [x] `/compact` 不发送普通用户请求，不写入规范对话。
- [x] `/compact` 绕过自动阈值和自动熔断，但受会话级互斥保护。
- [x] 自动压缩状态、完成结果和失败原因在 TUI 中可见。
- [x] `prompt_too_long` 触发一次紧急压缩和一次原请求重试。
- [x] 紧急重试再次撞墙时不递归重试。
- [x] 自动摘要连续失败三次后熔断，成功一次后清零。
- [x] 手动和紧急压缩不受自动熔断影响。
- [x] Artifact 账本、文件追踪、模型视图和熔断状态并发访问无竞态。

## 任务质量回归

- [ ] 压缩前后都能完成文件定位任务。
- [ ] 压缩前后都能继续未完成的待办任务。
- [ ] 压缩后模型能通过 Artifact 读取精确文件片段和完整错误。
- [ ] 压缩后模型不会把推测当成确认事实。
- [ ] 用户明确的偏好、否定和验收约束在压缩后仍可恢复。
- [ ] 摘要降幅、延迟、失败率和任务完成率都有可观察记录。
