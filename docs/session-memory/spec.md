# KCode 项目指令与会话持久化 Spec

## 背景

KCode 0.5 已具备进程内的完整对话记录、会话内上下文压缩，以及会话目录中的工具结果落盘。但进程退出后，对话无法恢复；System Prompt 中虽有项目指令和长期记忆槽位，但尚无加载来源。

本期只解决“静态项目知识 + 忠实会话恢复”：用分层 `KCODE.md` 向新会话提供稳定指令，用追加式 JSONL 保留真实会话事件，并由用户通过 `/resume` 主动恢复。自动笔记与 LLM 记忆治理留给第二期。

## 目标

- G1：启动时加载三层 `KCODE.md`，按“用户 < 项目 < 本机项目”解决冲突。
- G2：以厂商无关 JSONL 追加保存完整对话消息，按逻辑检查点刷盘。
- G3：通过 `/resume` 搜索和选择历史会话，恢复有效模型消息链，并在界面重绘对话轮次。
- G4：恢复时处理坏行、悬空工具调用、模型差异和上下文超限。
- G5：`/clear` 保留旧会话存档并开始新会话。
- G6：持久化失败时明确降级；历史文件默认防误提交并尽可能收紧本地权限。
- G7：本期不让 LLM 自动创建、更新或删除长期记忆。

## 功能需求

### 项目指令

- F1：启动时依次读取用户级 `~/.kcode/KCODE.md`、项目级 `<project>/KCODE.md`、本机项目级 `<project>/.kcode/KCODE.md`；缺失文件静默跳过。
- F2：冲突优先级固定为“本机项目 > 项目 > 用户”。每层指令带明确来源标签后注入项目指令槽位，不得覆盖 KCode 的系统安全约束。
- F3：只展开独占一行的 `@include <relative-path>`。路径相对当前文件解析，解析符号链接后仍须位于所属根边界内。
- F4：include 最大深度为 5，按当前展开链检测环路。缺失、越界、二进制、非 UTF-8 和不可读的 include 文件跳过并显示启动警告，警告不混入指令文本。
- F5：三层指令的完整展开结果总计不超过 32 KiB，只在完整内容边界停止。指令在启动时加载一次，运行期间不热更新。

### 会话日志

- F6：每个新会话使用 `YYYYMMDD-HHMMSS-xxxx` ID，并与已有工具结果目录共享同一 session ID。空白会话不创建存档。
- F7：`conversation.jsonl` 使用带版本号的厂商无关格式：先写会话元数据，再追加 KCode 内部用户消息、助手消息、工具调用和工具结果。不保存厂商原始 continuation payload。
- F8：日志只追加真实完整对话消息，不写 compact 标记，不用摘要替换原始历史。
- F9：无工具轮次在最终回答完成时写入“用户 + 助手”检查点；工具轮次在每个完整工具批次后写入新增消息，最终回答再写一个检查点。取消或失败时只保留已进入完整对话的检查点。
- F10：每个检查点按顺序在工作线程中执行写入、flush 和 fsync。不承诺跨平台固定 10ms，但不得在 Textual 事件循环中执行阻塞磁盘操作。
- F11：单进程写入严格串行化；同一历史会话同一时间只允许一个 KCode 进程续写，异常退出后租约可安全释放。
- F12：写入失败后当前内存会话继续运行，但界面持续显示“持久化不完整”，不得静默声称已保存。
- F13：会话目录和文件尽可能收紧为当前用户访问；已知敏感值继续脱敏；`.kcode/sessions/` 默认被 Git 忽略。文档必须说明任意工具内容仍可能被明文保存。

### 会话恢复与界面

- F14：新增 `/resume`，仅在 Agent 空闲时可用。列表只包含有效、非空且不是当前 runtime 的版本化会话，按最后活跃时间倒序。
- F15：列表展示首条用户消息标题、相对时间、原模型和日志大小；支持上下键、搜索、Enter 和 Esc。
- F16：恢复时逐行读取规范化消息。坏行跳过并显示数量警告；未知 schema 版本拒绝恢复，但不影响其他会话。
- F17：悬空工具调用只在恢复后的内存消息中补“状态未知、需要核实”的错误结果，不写回 JSONL；没有对应调用的孤立结果不放入模型历史。
- F18：使用当前 Provider 和模型恢复。与原模型不同时明确提示。恢复历史超过当前上下文预算时，先使用现有压缩机制生成模型视图，原始日志不变。
- F19：每次恢复都为首个 Agent 轮次加入不落盘的临时系统提醒，包含最后活跃时间，并要求重新核实可能过期的文件和外部状态。
- F20：界面重绘用户消息与最终助手回复；工具链只显示简短状态，模型仍接收完整有效历史。
- F21：恢复成功后继续向原 session 追加。目标会话正被其他进程使用时，标记为占用并拒绝续写。
- F22：`/clear` 关闭当前 writer、保留旧存档、清空界面与上下文，并开始新的空白 session；不删除历史。
- F23：关闭应用时等待已提交检查点完成写盘并释放会话租约；超时或失败必须可见。

## 非功能需求

- N1（响应性）：指令加载和会话扫描不得执行无界读取；磁盘刷盘、目录扫描和大日志解析不得阻塞 Textual 事件循环。
- N2（持久性）：每个成功检查点在报告“已保存”前必须完成 flush + fsync；异常中断后，最后一个损坏或未完成记录之前的完整记录仍可独立解析。
- N3（并发安全）：进程内写入严格有序；跨进程禁止同时续写同一会话；进程退出后不得留下永久占用。
- N4（数据安全）：本期不自动删除任何会话。所有路径均经解析和边界校验；会话日志、include 和锁文件不得通过 `..` 或符号链接逃出允许目录。
- N5（隐私）：会话存档默认不进入 Git，使用已有敏感值脱敏并设置合理本地权限。文档明确“任意已读取内容可能被保存”，不声称完全秘密检测。
- N6（兼容性）：继续支持 Python 3.11+、macOS、Linux 和 Windows。没有指令或历史目录时行为与当前 KCode 一致。旧 session ID 和仅含 `tool-results` 的目录不展示、不迁移、不删除。
- N7（格式演进）：JSONL 带 schema version；未知版本安全拒绝，不得按当前结构猜测解析。
- N8（错误隔离）：单个指令文件、会话目录或坏记录失败不拖垮启动和其他会话；所有影响用户恢复能力的错误必须可见。
- N9（可测性）：加载、序列化、恢复修复、列表构建和租约逻辑可脱离真实 Provider 与网络测试；默认测试不产生 API 费用。
- N10（现有行为）：权限系统、MCP、Agent Loop、上下文压缩和 Provider 适配器在没有新输入时保持现有行为。
- N11（可审计性）：JSONL 只记录真实完整对话事件。恢复期合成提醒、悬空工具补位和压缩摘要均与原始日志分离。
- N12（文档一致性）：规范统一使用 KCode 的 `.kcode`、`KCODE.md` 和内部消息术语，不引用其他项目的路径、类名或不存在的回调。

## 不做的事

- 不做自动笔记提取、四类 Memory 文件、`MEMORY.md` 注入和 LLM 去重。
- 不允许 LLM 自动更新或删除长期记忆文件。
- 不做 30 天自动清理，不提供会话删除命令。
- 不做会话日志加密、云同步、团队同步或跨设备迁移。
- 不做向量数据库、Embedding、RAG 或笔记全文搜索。
- 不保存 Provider 专属原始响应状态，不保证跨模型恢复后的回答风格完全一致。
- 不自动恢复最近会话；每次启动先进入新空白会话，由用户主动 `/resume`。
- 不做会话合并、分叉、重命名、导入导出。
- 不做 `KCODE.md` 文件监听和运行时热更新。
- 不迁移、不删除现有旧格式 `.kcode/sessions` 数据。

## 验收标准

### 项目指令

- AC1：三层文件同时存在且规则冲突时，生成内容带来源标签，并明确得到“本机项目 > 项目 > 用户”的约束；没有任何文件时正常启动。
- AC2：普通、五层嵌套和重复但非环路 include 正常展开；第六层、真实环路、越界路径和指向边界外的符号链接被拒绝并显示警告。
- AC3：二进制、非 UTF-8、缺失和无权限 include 不进入 Prompt；一个失败不影响后续合法 include。
- AC4：展开总量超过 32 KiB 时只注入预算内的完整内容，启动界面显示未加载来源，Prompt 仍可发送。
- AC5：运行期间修改 `KCODE.md` 不影响当前进程，重启后才生效。

### 会话写入

- AC6：新会话 ID 符合时间格式；第一条成功轮次后出现同 ID 的 `conversation.jsonl`，工具产物存在时其目录共享该 ID；空白会话不落盘。
- AC7：纯文本轮次恢复为同样的用户/助手消息；工具轮次恢复后调用 ID、名称、参数、结果和顺序一致。
- AC8：执行手动或自动压缩前后，JSONL 仍只包含原始真实消息，不出现摘要替换或 compact 标记。
- AC9：模拟慢 fsync 时 Textual 事件循环仍能处理界面事件；检查点未完成前不显示已安全保存。
- AC10：模拟写盘失败后，对话可继续，界面持续显示持久化不完整，不显示虚假的完整保存。
- AC11：会话目录被 Git 忽略，已知 API Key 不出现在日志中，支持权限控制的平台上文件权限符合要求。

### 会话恢复

- AC12：`/resume` 的列表、搜索和预算内恢复不调用模型；当前 runtime 不作为候选，其他会话按时间倒序展示标题、时间、模型和大小，搜索、上下键、Enter、Esc 均可用。只有 F18 的超预算恢复会调用当前 Provider 生成压缩视图，并在切换前完成或失败回滚。
- AC13：恢复同模型会话后，下一次 Provider 请求包含完整有效历史；界面重绘旧用户/助手轮次，但不展开大工具结果。
- AC14：插入一条坏 JSON 后，其余有效记录仍可恢复，界面报告跳过数量；未知 schema 会话显示不可恢复原因。
- AC15：悬空工具调用得到内存中的“状态未知”错误结果，Provider 请求合法，原 JSONL 字节不变；孤立结果不发送给模型。
- AC16：使用不同当前模型恢复时成功并显示差异提示，原模型元数据不被改写。
- AC17：超预算会话在恢复阶段调用现有压缩机制，模型视图可装入窗口，原日志不变；压缩失败时不进入伪成功状态。
- AC18：每次恢复都加入临时过期提醒；该提醒出现在恢复后首个 Agent 轮次的模型请求中，但不出现在 JSONL。
- AC19：两个进程不能同时续写同一会话；活跃租约拒绝第二个进程，持锁进程退出后可重新获取。
- AC20：恢复后新消息追加到原会话；`/clear` 后旧文件停止增长，新内容使用新 session ID，旧会话仍可再次恢复。
- AC21：正常退出等待写盘并释放租约；异常退出后，先前完成的检查点可恢复。

### 兼容与回归

- AC22：没有新文件、只有旧 session ID 或只有旧 `tool-results` 目录时，KCode 正常启动，旧数据不展示、不迁移、不删除。
- AC23：现有 Provider、MCP、权限、工具、上下文压缩和 TUI 测试全部通过；新增测试默认不联网、不调用真实模型、不产生费用。
- AC24：端到端场景通过：启动加载三层规则 → 完成含工具调用的会话 → 退出 → 再启动搜索并恢复 → 收到过期提醒 → 继续对话 → `/clear` 开启新会话。
